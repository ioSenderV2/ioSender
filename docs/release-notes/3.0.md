## What's new in 3.0

3.0 is the first major version since the 2.x line began, and it carries 203 changes — 63 new
features, 99 fixes and 41 revisions — everything merged since 2.41 shipped in August.

Two things earn the version number. The machine engine no longer lives inside the desktop
application: it compiles as a plain .NET 8 library, and the SVG-to-laser path builds without any
Windows UI at all, so the same code can run on a Raspberry Pi appliance. And macros, g-code programs
and typed commands finally share one streaming engine, one dispatch path and one pacer — which is
what makes a Work Order a single press rather than a sequence you shepherd.

Everything else in here is downstream of those two, or is the long tail of making the machine refuse
what it used to attempt.

### It refuses things it used to attempt

This is the part worth reading even if you skip the rest.

A 600 mm ruler was once run on a 400 mm machine: it drove 200 mm past the end of X and sat grinding
against the stop. The extents were on screen the whole time and nothing ever compared them to the
travel limits. Machine Setup three times reported a trashed configuration when the controller was
correct every time — the page was inventing zeros for travel, steps/mm and max rate, and Apply was
one press from sending a zero travel limit with soft limits switched on. A connect could finish with
none of the controller's settings read, say nothing about it, and then tell a probe to seek to Z
−9998. A 32 mm job was refused for spanning 858 mm, because machine-coordinate park moves were being
measured as if they were work coordinates.

All of those now check, and where a check cannot be made honestly, 3.0 says so instead of guessing. A
soft-limit alarm names the axis that ran out of travel and by how much, shows the sum and the line
that asked for it — and prints nothing at all rather than inventing a number when it cannot resolve
the coordinate frame. A fixture origin taught too close to a limit is refused when you teach it, not
mid-job after the tool has parked and you have already fitted the probe.

The one with the widest reach: a block ioSender could not parse used to be **silently discarded**,
which meant the program the controller ran was not the program on your screen. Unparsed blocks are
now sent verbatim.

### Probing and machine setup

The largest single area of work, and most of it came from running the machine and finding what hurt.

The tool-length reference sequence is now a macro on the controller rather than a second copy emitted
inline, its downward seek is derived from the stored baseline instead of a fixed 90 mm — so changing
your toolsetter no longer breaks it — and the V-bit scratch method is back for machines with no 3D
probe, sitting alongside the probe method rather than replacing it.

Corner probing has one code path instead of several, its prompts name the probe and the tip, and it
no longer stops to demand you trigger the probe by hand and then press Start a second time to get
past it. The four corner buttons and the centre bullseye used to look dead when they declined to
move, and their safe-Z retract aimed at the limit switch itself.

A false trigger is no longer accepted as a measurement: the fast and slow probes have to land in the
same place. If a cycle aborts with the tool resting on the plate, Z lifts to machine zero on its own
and reports what the probe pin says afterwards.

Squareness gets three new readings. A scribed rectangle inset 10 mm from the measured frame turns an
angular error into a taper you read with calipers. A second tab makes the square the artifact and the
probe the reader, at 0.002° rather than 0.01°. And flipping the square and measuring again splits the
result into the square's own error and the machine's. The four probed corners, the measured size and
the spoilboard Z now survive a restart, with the measurement's date beside the readout.

The spoilboard stopped being a guess. Two features used to ask the machine how far it could travel
and call the answer the board; the board's extent is now its own fact, entered in Machine Setup. A
new surfacing routine takes one slow plunge at the board's high point, cuts a rule in the pocket, and
then offers OK to surface or Cancel with nothing cut but that pocket.

Height mapping became a workflow rather than a tab. It publishes the program it is about to send,
follows the run through Steps → Program → Surface Map, logs every probed height, and can map a whole
table before any origin is set. Retry carries on from the point that failed instead of discarding
fifteen good readings, Stop works during the run's longest unattended moves, and a map can be applied
to a work order — with a refusal when the map no longer matches the setup it was probed against.

### Work Orders: text, artwork and drawings

Text can be engraved with a single-stroke font and a V-bit, or carved from any installed font's true
outlines in depth-varying passes, and fitted inside a line, circle, oval, square or rectangle.

Any .svg can be picked per toolpath and carved with the same engine, passes and preview as text — and
then inverted. A **Negative** tick carves the space around the artwork instead of the artwork, so the
logo stands proud inside a recessed panel; a **Panel** choice can use the artwork's own enclosing
contour as the boundary, so a circular badge carves only inside its circle. **Clear floor** pockets
the carve's floor flat with an end mill at exactly the depth the V-bit left it, and **Mark** rides a
V-bit's tip along an outline for a marking groove, optionally dashed with a whole number of periods
so the pattern meets itself.

Carve depth can be capped so hairline lettering keeps its full depth while wide areas flatten off and
clear. Square-cornered parts get dogbone corner reliefs so they drop in instead of fouling on the
radius a round cutter leaves. Toolpaths can be collected under a named group and enabled as a set,
copied as a group with per-member ticks, and a run-time substitution can drop a locating dimple at
every hole centre without disturbing the work order.

Right-click the stock diagram and you get a dimensioned PDF: the stock measured, every toolpath
ballooned and drawn in its own colour, and a feature table giving each one's position, geometry,
operations and tooling against the same balloon letters.

### Lasers

A diode laser on plain Grbl is a supported machine now, not an afterthought. SVG artwork becomes
laser g-code as outlines or shaded fill; a racked gantry is squared in software by entering two
diagonals and the side of a burned square; and generated jobs declare their power and feed as named
parameters at the top of the file, so a job is retuned by editing four numbers rather than
regenerating it.

A warning that came from burning real cedar: a fill is a raster, so halving the line interval doubles
the energy per square millimetre. A fill at what looked like reasonable numbers removed nearly 7 mm
of material, and nothing on the tab said why.

### It stops hanging, and it got faster

Forty controller waits that could spin for ever — responsive, and completely ignoring you — now end.
Silence from the controller during a homing cycle or a firmware upload is no longer read as a dead
link. A command answered with an error stops the wait immediately instead of running to timeout. A
board left in check mode by an earlier session used to loop for ever. An unowned message box left the
app beeping at every click and refusing to close, with Task Manager the only way out.

A 220,000-line program went from 32 seconds to under 3, and the console no longer freezes the
application while it loads. V-carving a script font compiles in seconds rather than minutes. A
43,000-block rebuild raises one notification instead of 43,000. And a loaded program now tells you
its compile progress and an estimated run time.

### The screen is yours again

The bottom status bar is replaced by a purpose-built run strip — and if you preferred the original,
**Classic run strip** cuts it back to what the first ioSender had, inline MDI box and status line
included. A **Layout:** selector in the menu row switches between named screen arrangements and saves
the one you are leaving; ioSenderClassic and DefaultV3.0 ship with the build. Configuration overlays
let you adopt someone else's screen layout without touching your machine settings, macros or
fixtures, reversibly.

Keyboard handling was quietly broken in a way that is obvious once stated: jogging worked on the Job
tab and nowhere else, and shortcuts worked on the top-level tabs and nowhere else. Both now work in
every window, dialogs included, and stop only while you are typing. The manual has a menu item and a
bindable key, and opens at the topic for the screen you are on — and every topic a September audit
listed as missing has been written.

There is also a log an operator can actually read: what a connect established, what a run did, and
what a settings change altered, with the old value and the new one.

### Running a job

A running job can be paused at the next block boundary, parked at G30 with the spindle off, inspected
and then resumed. On any file containing a tool change the program list groups into collapsible
toolpaths, and one of them — or everything from one onward — can be run on its own. Generate loads
the program and takes you to the Job tab, so Run is pressed against what is on screen.

A few-pound camera remote can answer prompts, feed-hold a running job and resume a held one, or be
bound as a full pendant with each button's job set per machine state, including in alarm.

### Feeds, speeds and tooling

The feeds-and-speeds chart recommended 24,000 mm/min on a gantry that maxes out at 16,510. grblHAL
clamps rather than complains, so the chip load quoted was 0.400 mm/tooth while the tool actually saw
0.275. A helical bore's feed is now compensated where the cutting edge really does outrun the tool
centre, and left exactly as entered on a full-immersion helix — where compensating it starves the cut
and rubs the cutter to destruction.

### Backup and restore

Two things were being snapshotted at the same moments — the controller's settings and ioSender's own
configuration — and only one of them had a restore. Each row is now a point in time you can restore
either half of, or both.

## Upgrading from 2.41

- **Your screen layout is kept.** A brand-new installation starts on the ioSenderClassic preset; an
  upgrade keeps whatever arrangement it already has.
- **Set your spoilboard extent in Machine Setup.** It used to be derived from the machine's travel
  limits. Surfacing and board-extent checks read it from Machine Setup now, and say so plainly when
  nothing declares one.
- **Existing fixtures are converted as they load.** Test position writes the corner it probed
  straight into the fixture, replacing the reference you jogged to by eye.
- **Sounds are off by default.** Settings → User Interface → Sound can attach one to a limit switch,
  the probe, or the machine going into alarm.
- **Loading an SVG as a laser job is off by default** and enabled per launch with
  **-enableSVGLaserJob**.
- **Firmware 2.0.0 and later:** that firmware derives its version from a git tag, which dropped the
  build date from its version report. Ten date-gated feature tests in 2.41 read that as zero, and two
  of them switched a legacy bug workaround **on**. 3.0 is the release that fixes it — if you are
  running firmware built from late October onward, you want this version.
