Client/server roadmap

Status of the split and the web client. Updated 2026‑08‑09. Branch pr/portable-core.
Two lists, two namings — on purpose. The split uses numbered steps 1–7; the web client uses lettered phases A–H. They used to both be “steps” and collided. When something says “6a” it means a split step; a letter always means a web‑client phase.

Part 1 — The split (steps 1–7)

Goal: a portable server owning the connection, machine state, the program and playback; the client becomes replaceable. Every step left a shippable app.

Part 2 — The web client (phases A–H)

TypeScript + three.js, served by the host. Every phase ships with its conformance tests; a command without tests does not ship. Tiers refer to API Reference §9.

Settled, for the record

DecisionOutcome
Client stackTypeScript + three.js, served as static files. No client install.
Server hostSelf‑contained .NET 8 process. WPF hosting is scaffolding for 6a only.
Multi‑clientOne writer (operator lease), unlimited viewers. The stopping set needs no lease.
WPF read‑only workCut. Two‑rig strategy instead: WPF drives real iron, the web client writes against the simulator.
MachineField on the wireField names, not a bitmask — JS coerces bitwise ops to int32 and the set is past bit 33.
Deploymentdotnet publish --self-contained; no end user installs a runtime.
